# Transaction Logging Implementation

## Overview

Transaction logging has been successfully integrated into the ATM ISO 8583 Gateway. All ISO 8583 transactions are now automatically persisted to the database with comprehensive details.

## Database Schema

The `transactions` table is already created via Flyway migration (`V1__init_transactions.sql`):

```sql
CREATE TABLE transactions (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    transaction_ref VARCHAR(255),
    mti VARCHAR(10),
    status VARCHAR(50),
    response_code VARCHAR(10),
    response_description VARCHAR(255),
    processing_time_ms BIGINT,
    error_message VARCHAR(255),
    request_fields CLOB,
    response_fields CLOB
);

CREATE INDEX idx_transactions_transaction_ref ON transactions (transaction_ref);
CREATE INDEX idx_created_at ON transactions (created_at);
CREATE INDEX idx_transactions_mti ON transactions (mti);
```

## Implementation Details

### 1. Entity Model

- **Location**: `com.atm.iso8583.model.Transaction`
- **Features**:
  - Auto-generated ID
  - Automatic timestamp management (`@PrePersist`, `@PreUpdate`)
  - JSON storage for request/response fields (CLOB)
  - Indexed fields for efficient querying

### 2. Repository

- **Location**: `com.atm.iso8583.repository.TransactionRepository`
- **Query Methods**:
  - `findByTransactionRef(String)` - Find by transaction reference
  - `findByMti(String, Pageable)` - Find by MTI with pagination
  - `findByResponseCode(String, Pageable)` - Find by response code
  - `findByCreatedAtBetween(Instant, Instant, Pageable)` - Date range queries

### 3. Service Layer

- **Location**: `com.atm.iso8583.service.TransactionService`
- **Methods**:
  - `saveTransaction(request, response)` - Persist transaction
  - `getTransactionsByMti(mti, pageable)` - Query by MTI
  - `getTransactionsByResponseCode(code, pageable)` - Query by response code
  - `getTransactionsByDateRange(start, end, pageable)` - Query by date range
  - `getTransactionByRef(ref)` - Find by transaction reference

### 4. Integration

- **Location**: `com.atm.iso8583.service.Iso8583GatewayService`
- **Changes**:
  - Injected `TransactionService` dependency
  - Added `transactionService.saveTransaction(request, response)` call in the `finally` block
  - Ensures all transactions are logged regardless of success or failure

## What Gets Logged

Each transaction record includes:

- **Transaction Reference**: Client-provided reference for tracing
- **MTI**: Message Type Indicator (e.g., 0200, 0210)
- **Request Fields**: Complete ISO 8583 request fields as JSON
- **Response Fields**: Complete ISO 8583 response fields as JSON
- **Response Code**: ISO 8583 response code (e.g., 00 for success)
- **Response Description**: Human-readable description
- **Processing Time**: End-to-end latency in milliseconds
- **Status**: SUCCESS or ERROR
- **Error Message**: Details if transaction failed
- **Timestamps**: Created and updated timestamps

## Usage Examples

### Automatic Logging

All transactions sent via the `/api/iso8583/send` endpoint are automatically logged:

```bash
curl -X POST "http://localhost:8080/api/iso8583/send" \
  -H "Content-Type: application/json" \
  -d '{
    "mti":"0200",
    "transactionRef":"ATM-20260414-0001",
    "fields":{
      "2":"1234567890123456",
      "3":"000000",
      "4":"000000010000",
      "11":"123456",
      "41":"12345678",
      "49":"840"
    }
  }'
```

### Querying Transactions (via Service)

```java
// Find by transaction reference
Transaction txn = transactionService.getTransactionByRef("ATM-20260414-0001");

// Find all 0200 transactions
Page<Transaction> purchases = transactionService.getTransactionsByMti("0200", pageable);

// Find approved transactions
Page<Transaction> approved = transactionService.getTransactionsByResponseCode("00", pageable);

// Find transactions in date range
Page<Transaction> recent = transactionService.getTransactionsByDateRange(
    startTime, endTime, pageable
);
```

## Database Configuration

The application uses H2 in-memory database by default (configured in `application.yml`):

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:atm_iso8583
    driver-class-name: org.h2.Driver
  jpa:
    hibernate:
      ddl-auto: validate
  flyway:
    enabled: true
    baseline-on-migrate: true
```

For production, switch to PostgreSQL or another persistent database by updating the datasource configuration.

## REST API Endpoints

The following endpoints are now available to query transaction history:

### Get Transaction by Reference

```bash
GET /api/transactions/{transactionRef}

# Example
curl http://localhost:8080/api/transactions/ATM-20260414-0001
```

### Query Transactions with Filters

```bash
GET /api/transactions?mti={mti}&responseCode={code}&startDate={iso8601}&endDate={iso8601}&page={page}&size={size}

# Examples:

# Get all 0200 transactions (first page, 20 items)
curl "http://localhost:8080/api/transactions?mti=0200"

# Get approved transactions
curl "http://localhost:8080/api/transactions?responseCode=00"

# Get transactions in date range
curl "http://localhost:8080/api/transactions?startDate=2026-04-14T00:00:00Z&endDate=2026-04-14T23:59:59Z"

# Get last 24 hours (default if no filters provided)
curl "http://localhost:8080/api/transactions"

# Pagination
curl "http://localhost:8080/api/transactions?mti=0200&page=0&size=50"
```
